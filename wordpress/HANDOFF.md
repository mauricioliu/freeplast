## 4. Accessibility and responsive mechanical observations

Recorded by `npm test` (issue #13 sections) as **mechanical observations,
not human approval** — no pixel rendering and no human verdict is claimed:

- **Keyboard:** native controls in logical DOM order, `<details>`
  disclosures, the announced mobile sheet, and a focusable linked error
  summary (`tabindex=-1`, `#fragment` focus, `role=alert`) whose links
  target real labelled fields.
- **Focus:** `:focus-visible` outlines parsed from the shipped CSS; WCAG AA
  contrast computed for the frozen palette pairs (4.5:1 text/controls,
  3:1 headings/focus).

  and basket retained after every rejection.

  768, 1024 and 1440 px with viewport meta everywhere; adaptation only
  through the declared 768/1024 breakpoints.

## 5. Operations runbook (reproducible by another operator)

Server-side commands run on OpenClaw; the stack lives in
`/opt/freeplast-wordpress` with sources at
`/opt/freeplast-wordpress-src` (see `DEPLOYMENT.md` for the full resource
record). WP-CLI on the server goes through the profile-gated sidecar:
`docker compose --env-file .env run --rm cli wp …`.

### 5.1 Deploy, update, redeploy

```bash
rsync -a --delete <repo>/wordpress/ openclaw:/opt/freeplast-wordpress-src/
ssh openclaw 'TLS_CERT_PATH=… TLS_KEY_PATH=… WORDPRESS_ADMIN_EMAIL=… \
  bash /opt/freeplast-wordpress-src/infra/deploy.sh /opt/freeplast-wordpress-src'
```

`deploy.sh` runs the read-only `preflight.sh` first (any collision aborts),
generates secrets on the server, validates Compose before `up -d`,
bootstraps WordPress (es_CL, America/Santiago, HTTPS URLs, `blog_public 0`),
synchronizes the catalog behind a zero-change dry-run gate, backs up Nginx,
installs the vhost, `nginx -t`, reloads, and walks the HTTPS verification.
Re-running it against the deployed stack updates in place (secrets kept,
`wp core is-installed` guarded).

### 5.2 Backup and restore

```bash
ssh openclaw 'bash /opt/freeplast-wordpress-src/infra/backup.sh'
```

Dumps the database (`mariadb-dump`, password via the container
environment), archives the whole WordPress volume (`tar`), writes
SHA-256 sums outside the live volumes into
`/root/freeplast-wordpress-backups/<UTC-stamp>/`, then **rehearses the
restore** into the temporary project `freeplast-wordpress-restore`
(loopback 8093), verifies the restored `fp_product` count matches the
live stack and tears the rehearsal down. A real restore uses the same two
artifacts: recreate the stack (`deploy.sh`), pipe `db.sql` through
`mariadb` in the db service and unpack `files.tgz` into
`/var/www/html` — exactly the rehearsed sequence. Run before every
catalog import, plugin migration or release.

### 5.3 Rollback (bounded to the new resources)

```bash
ssh openclaw 'bash /opt/freeplast-wordpress-src/infra/rollback.sh'
# named volumes retained; after explicit owner approval only:
ssh openclaw 'bash /opt/freeplast-wordpress-src/infra/rollback.sh --purge-volumes'
```

Removes only the approved-hostname vhost (after `nginx -t`) and the
`freeplast-wordpress` Compose project; neighbors are verified untouched.

### 5.4 Catalog synchronization

The Catalog Source is version-controlled in the repository — never edited
through WordPress:

```bash
# 1. edit wordpress/data/products.json in the repository (reviewed change)
# 2. ship it to the host and refresh the stack bundle copy
rsync -a <repo>/wordpress/data/ openclaw:/opt/freeplast-wordpress-src/data/
ssh openclaw 'cp /opt/freeplast-wordpress-src/data/products.json \
  /opt/freeplast-wordpress/bundle/catalog/products.json'
# 3. synchronize behind a dry run (run from /opt/freeplast-wordpress)
ssh openclaw 'cd /opt/freeplast-wordpress && docker compose --env-file .env run --rm cli \
  wp freeplast catalog sync --file=/bundle/catalog/products.json --dry-run'
ssh openclaw 'cd /opt/freeplast-wordpress && docker compose --env-file .env run --rm cli \
  wp freeplast catalog sync --file=/bundle/catalog/products.json'
# 4. the repeated dry run must report created=0 updated=0 … errors=0
```

Validation is complete before any mutation (unknown keys, duplicate
identity, invalid slugs/URLs, unsupported color options, media checksums);
missing products are warnings only; archiving requires an explicit source
lifecycle change.

### 5.5 Sales administration (operate a quote from new to closed)

1. Sign in at `https://freeplast.mliu.site/wp-login.php` with a Ventas
   Freeplast (or administrator) account.
2. Open **Cotizaciones**: sort/search by reference, company, email, created
   date or Request Status; open the reference.
3. The detail separates immutable Submitted Details from correctable
   Current Contact Details (corrections update the current copy and record
   a PII-free history event); append internal Sales Notes; the item
   snapshots, dispatch destination and distance state render read-only.
4. Move the Request Status new → contacted → quoted → won/lost (skips
   permitted; cancelled from new/contacted/quoted); terminal states reopen
   only through the explicit Reabrir action (back to contacted).
5. Quote Requests are retained indefinitely; anonymous basket sessions
   expire after 30 days (daily sweep) — no automatic deletion exists.

### 5.6 Notification retry

The Cotizaciones detail carries a **Notificaciones** section per channel
(sales/customer): state, attempts, last attempt and a **Reenviar** action
for failed deliveries (nonce + capability guarded; a delivered channel is
never re-sent). The internal distance retry sits in the same detail
(**Recalcular distancia**). Delivery runs on the scheduled event — system
cron on staging.

### 5.7 Warehouse (dispatch origin) configuration

The origin of every distance calculation is the stored option, seeded by
migration 7 to the provisional *Camino El Arrayán 52, San Francisco de
Mostazal*:

```bash
ssh openclaw 'docker compose --env-file .env run --rm cli \
  wp option update fp_dispatch_origin "<approved origin address>"'
```

Calculations additionally require the environment-supplied Google key
(`FREEPLAST_GOOGLE_API_KEY` in the stack `.env`, Places + Routes
restricted, never committed); without it distances persist as pending and
staff can retry later. Distance semantics (one-way/round trip/duration)
stay this configuration plus the provider adapter until the client answers.

### 5.8 Staging mail mode

`FREEPLAST_CQ_MAIL_MODE` in the stack `.env` selects `suppress` (default,
non-delivery), `redirect` (needs `FREEPLAST_CQ_MAIL_TO`) or `allowlist`;
`live` is production-only and `verify.sh` fails if it is ever set here.
After changing `.env`, reconcile with
`docker compose --env-file .env up -d` and re-run `verify.sh`.

`dist/CHECKSUMS.sha256` additionally carries a per-file SHA-256 manifest of
every shipped theme/plugin file. From `wordpress/dist`,
`sha256sum -c CHECKSUMS.sha256` verifies both packages and every source
file the packages were built from. The ZIPs are
deterministic stored archives (fixed timestamp, sorted entries), so
`npm test` rebuilds byte-identical packages and records the digests in
`VERIFICATION.md` §Shipped artifact checksums; `unzip -t` validates each
archive. Install through wp-admin Appearance → Themes / Plugins → Add New
→ Upload, or by unpacking into `wp-content/` on the server.
