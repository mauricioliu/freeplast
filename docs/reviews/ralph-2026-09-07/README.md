## Standards

Full independent report: [standards.md](standards.md). Standards are the repo's ADR-0001 and documented implementation contracts in `wordpress/BUILD-DECISIONS.md`, not generic stylistic preferences.

1. **ST-01 · P1 — The posted attempt identity is discarded.** `wordpress/wp-content/plugins/freeplast-woo/freeplast-woo.php:618–620` reads `fpw_attempt` from `WC_Checkout::get_posted_data()`, but that field is not registered in Woo's checkout fields or added by its posted-data filter. Woo drops it; the adapter substitutes the current session token. An old form that misses early recovery can become a different attempt. This contradicts `BUILD-DECISIONS.md:37–40` (resubmissions retain attempt identity). Register the field in normalization or explicitly read/validate the submitted token. [Offline evidence](evidence/probe-posted-token.log).
2. **ST-02 · P1 — Identity verification does not prevent unsafe staging mutations.** `wordpress/scripts/verify-ventas-role.py:139–151` ignores the return from `ok('identity_verified', ...)`. The helper records failure but continues to add a note and attempt writes against the supplied `--order-id`. This contradicts `BUILD-DECISIONS.md:27` (verify synthetic-record identity before mutation). Abort dependent probes on failed identity, preserving account cleanup. [Entire-script execution with all network mocked](evidence/probe-staging-identity.log) reaches the note POST after logging identity failure; no actual request was sent.
3. **ST-03 · P2 — The staging deletion test still conflates CSRF with authorization.** `wordpress/scripts/verify-ventas-role.py:188–191` sends the trash request without `_wpnonce`, then calls record survival `delete_denied`. It would pass even if deletion capabilities were granted. This contradicts the separate valid-nonce authorization evidence contract in `BUILD-DECISIONS.md:27`. Classify this as CSRF coverage and require a valid restricted-actor nonce for permission evidence. The disposable suite's separate valid-nonce test does not repair this staging test's claim.
4. **ST-04 · P3 — The documented shared pending predicate has only one consumer.** `wordpress/wp-content/themes/freeplast/assets/js/cart-quantity-feedback.js:157–159,206–207` adds `operationsPending()` for the CTA while verdict deferral retains its separate condition. `BUILD-DECISIONS.md:48` says both use the shared predicate. This is a documentation/implementation mismatch and a **heuristic Duplicated Code concern**, not proof that all operations need the same scope. Reconcile the intended semantics and the documentation; centralize if they truly should agree. The independent reviewer called this a hard violation; this aggregation qualifies its behavioral significance.

## Spec

Full independent report: [spec.md](spec.md). Findings are kept separate from Standards; ST-01/SP-02 and ST-02/SP-05 overlap, so counts are not nine distinct defects.

1. **SP-01 · P1 · #33 — Ventas can still write order lines through tax recalculation.** `freeplast-woo.php:318–333` omits `woocommerce_calc_line_taxes` from the denied AJAX actions. With the editor's valid `calc_totals_nonce`, `order_id`, and serialized item quantities, pinned `src/Internal/Orders/TaxesController.php:13–46` checks only `edit_shop_orders` and invokes `wc_save_order_items()`. It bypasses the editor-save guard, contradicting the role's read-and-private-note-only scope. Guard this native mutation route and audit the remaining native action family; add a valid-nonce regression. [Offline probe](evidence/probe-sales-tax-route.log) confirms a restricted actor passes the real adapter guard and reaches the pinned controller's persistence boundary. Nonce verification and persistence are test doubles; no native HTTP authorization or database write is claimed.
2. **SP-02 · P1 · #31/#32 — Unknown tokens can fold into an existing request and clear a new selection.** `freeplast-woo.php:616–622` has the normalization defect described in ST-01. Complete A, add new products without rendering checkout again, then replay with a valid checkout nonce and an unknown attempt token. Early recovery declines, but native checkout substitutes session token A and folds into it; Quotes' gateway empties the basket (`includes/class-quotes-payment-gateway.php:77–87`). This violates #32's safe answer for unknown attempts and new-selection preservation. The real normalized-data mismatch is reproduced offline; the downstream native gateway behavior is source-traced, not exercised over HTTP.
3. **SP-03 · P2 · #32 — Recovery expires when another request lands, not only at the declared lifetime.** `freeplast-woo.php:643–645` overwrites the sole `fpw_attempt_landed` record, while `875–877` requires it to match. Save A with the response lost, complete B, then retry A with its valid nonce inside the one-day recovery period: the session binding no longer matches and native checkout rejects the empty basket. Retain authorized per-attempt recovery bindings for their supported lifetime, or resolve through an equivalently authorized durable binding. This violates recovery “dentro de una vigencia definida.”
4. **SP-04 · P2 · #34 — Response headers unlock the CTA before the response body settles.** `cart-quantity-feedback.js:245–250` decrements the in-flight count when `fetch` resolves, which happens at response headers. After abort/replacement cleared the native pending flag, a slow body leaves `aria-disabled=false`, permits a click, and announces a false failure before Woo consumes the result. The intent is then deleted, so the successful quantity can arrive without replacing the false failure notice. This violates the requirement to block while a relevant mutation remains unconfirmed. Observe full request/response processing, not headers alone. [Probe and output](evidence/probe-response-body.log) use the real pinned store and a real `Response` instance with deferred `.json()`; after release the quantity becomes 7 but the failure message remains. This improves on the independent reviewer's initial plain-object response probe.
5. **SP-05 · P1 · #33 — The synthetic-record safety requirement remains unenforced.** Same implementation as ST-02. A historical `--order-id` can fail identity verification and still receive the test note and subsequent mutation probes, contrary to “Verificar explícitamente la identidad del registro de prueba antes de mutarlo.” Fail closed and use a newly provisioned synthetic record, not an arbitrary historical match.

No actionable scope creep was identified.
