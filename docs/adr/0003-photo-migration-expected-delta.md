# 0003 — Photo releases preserve the original record fingerprint through a bounded expected delta

The owner confirmed a **DATA** release of the prepared catalog photographs to the Staging Site on 2026-09-09. Photos are imported into WordPress's native Media Library and assigned through the existing featured-image pointers, inside the same sealed migration hook in restore trial and live install, under release-owned maintenance. They are not supplied by a parallel storefront image map or an automatic public-request migration.

The original full-record fingerprint remains authoritative: the immutable backup captures product identities, original image/pointer IDs, existing row-ID boundaries, manifest hash and original digest. Only new attachments that exactly match the approved photograph, alt, caption, provenance, native metadata and files can be excluded from the comparison; only the corresponding original `_thumbnail_id` rows are projected back to their captured values. Every old attachment and other protected row remains in the digest. Unknown or invalid changes remain visible as a mismatch, including new requests and unrelated catalog edits. The baseline is never recalculated after mutation.

A quotes-only fingerprint would weaken existing catalog protection; blindly accepting a new post-import digest would erase the evidence. Both alternatives are rejected. The snapshot travels through stdin from the hashed backup, not through arguments containing record data. New media/code are covered by the sealed bundle. This data release offers **paired recovery only**; restoring code alone cannot undo an image migration. A partial crash that cannot reproduce the expected delta stays closed for investigation/authorized recovery rather than adopting its new state.

This adds a data-migration boundary to [ADR-0002](0002-release-ceremony-as-contract.md); it does not remove any ceremony phase or authorize changes to the production site, product facts, availability, prices or Quote Requests.
